# DSH SuperTerminal 使用指南

[返回产品首页](https://github.com/Harzva/dsh-superterminal#readme) · [访问官网](https://harzva.github.io/dsh-superterminal/)

在 DSH 对话旁打开 **Side Terminal**，用自然语言说明目标，让 AI 检查文件、执行命令、修改代码并验证结果。也可以打开本机智能体 CLI，展开工作台自由分屏，或通过 **Terminal Group 终端讨论组** 邀请多个终端共同讨论。

## 开始使用

当前支持 **macOS、Node.js 24+ 和官方 DSH 0.1.1-rc.2**，可连接具有 OpenSSH 与 tmux 的远端终端。暂不支持 Windows 或其他 DSH 版本。

安装 alpha.16，然后重启所选 DSH 配置：

```sh
dsh plugin --profile web add https://github.com/Harzva/dsh-superterminal/releases/download/v0.1.0-alpha.16/harzva-dsh-terminal-0.1.0-alpha.16.tgz
```

在 DSH 输入栏点击 **终端**，或输入 **/terminal** 并选择“打开终端”。从旧版 DSH Terminal 升级时继续使用同一插件，无需额外安装第二份。

## 在对话旁开始工作

Side Terminal 默认打开在 DSH 右侧详情栏，拖动栏边缘即可调整宽度。点击标题栏的 **工具详情** 可返回 DSH 原有的命令输出和工具详情；点击 **×** 收起侧栏，任务继续运行。有多个终端时，侧栏内的切换条可直接选择目标终端，草稿与进程分别保留。

需要更多空间时点击 **展开工作台**，完成后点击 **回到侧边**，仍是同一组终端。空白对话或窗口太窄、无法显示右侧详情栏时，终端会先以浮层打开。

Side Terminal 提供两种关联方式：

- **绑定当前对话**：每个对话有自己的终端工作台。切换对话时，显示对应的终端；原来的任务继续运行。
- **独立工作台**：首次打开时沿用所选对话的工作区与权限，之后不随对话切换。适合需要持续查看的开发服务、检查任务或智能体。

切换关联方式会切换工作台，不会迁移正在运行的任务。绑定对话也不会自动把聊天内容交给终端中的智能体。

顶部工具栏提供 **新建终端**、**助手**、**协作** 和 **讨论组**，下方一行显示项目与会话归属。窄侧栏会将辅助入口收进 **更多**，分别对应 **解释与建议**、**交给 Agent** 和 **终端讨论组**。

点击 **新建终端** 即可进入 AI 任务。选中的空窗格还提供 **AI 任务** 与 Shell、Codex、Claude Code、Kimi Code 图标快捷入口；其余空窗格只显示 **添加终端**，点击后展开选择，已有布局不变。通过 **全部智能体** 或 **更多 → 智能体管理** 查找其他本机工具；在 **运行命令** 中可输入其他 CLI 名称。点击终端标题可以命名任务，例如“修复登录问题”。每个工作台最多打开 12 个终端。

## 直接说出任务目标

在 **AI 任务** 中输入“检查这个项目，修复失败的测试”，点击 **发送**。DSH 会在当前工作区执行，逐步显示工具操作和返回结果。输入区上方标明当前终端、模型和权限；第一次发送时沿用来源对话选中的模型，后续追问留在这个终端的执行会话中。

执行过程中可 **追加要求** 或 **停止**。一轮结束后继续输入即可追问；点击 **停止会话** 会清理该执行会话的后台资源，保留记录。下一次明确发送时可继续同一终端的历史。停止 AI 不会关闭 Shell；结束整个终端会同时停止它的执行会话。

长回复会保留开头与结尾，并标明省略的部分。通过 **分段查看完整结果** 读取 DSH 保存的原文；读取不会重新调用模型。原文仍属于原工作台与原执行会话，不能跨会话读取。

切换 **终端** 标签可查看、操作原来的 Shell 或智能体 CLI，切回 **AI 任务** 继续聊天。两种视图保留各自的内容。选中报错后点击 **直接处理**，会把目标和选区放入 AI 输入区，检查后再发送。

不同终端各自保留任务上下文、草稿与执行记录，不自动分享当前对话或其他终端的内容。任务使用来源会话的工作区与访问权限；权限不足的操作会失败，不会自动提权。来源权限变化后，需要停止原执行会话再继续。

同一服务最多同时执行 2 个 AI 任务，可为正在运行的任务追加要求。发送结果不确定时保留草稿，点击 **核对上次发送** 查询同一个请求，避免重复执行。刷新页面不会自动提交草稿或重跑任务；重启 DSH 后，已结束的终端需要重新打开。

## 安排与恢复你的工作台

默认使用浅色外观。在 **更多 → 外观** 中选择 **浅色**、**深色** 或 **跟随系统**，Side Terminal 与展开工作台会一起更新。偏好保存在当前浏览器中；切换外观不会重新启动终端，已有输出和草稿继续保留。

终端会改善低对比度文字的可读性。部分智能体 CLI 使用自己的配色，仍可在该 CLI 的设置中选择适合的外观。

- **自由分屏**：在工作台的 **更多 → 布局** 选择双栏、主次布局、六格或十二格；终端上的 **更多** 提供左右分割和上下分割。用键盘选择分屏后，焦点会进入新窗格，继续选择启动方式。
- **拖动调节**：拖动分隔线调整大小，双击均分；放大单个窗格以专注工作。放大后可用切换条或 **Alt + Shift + 方向键** 切换已有终端，继续保持放大；点击 **还原布局** 返回分屏。
- **收起终端**：点击窗格上的 **−**，任务继续运行。通过终端切换条或“已收起”列表可以再次显示。
- **结束任务**：点击窗格上的 **×**，确认后停止该任务。切换到其他终端或收起窗格时，会取消尚未提交的结束确认，任务继续运行。Side Terminal 顶部的 **×** 只收起整个侧栏。

运行窗格始终保留放大、收起与结束入口；分屏和加入讨论组收在该窗格的 **更多** 中。小窗格菜单与结束确认会适应当前空间，键盘也可完成选择和取消。结束确认中可用 Tab 或 Shift + Tab 切换选项，Esc 取消。底部的 **快捷键** 按需展开，可查看切换终端与放大操作，不占用终端正文空间。编辑输入框或使用助手、协作、智能体管理等辅助面板时，终端切换与放大快捷键不会抢占按键。

任务名称、智能体选择和布局保存在当前浏览器中，再次打开同一工作台时可恢复。仍在运行的终端会重新显示；必要时点击 **接管输入** 继续操作。

关闭或重启 DSH 会结束本机终端进程。原进程已不存在时，页面保留任务记录；点击 **重新启动** 会打开一个新终端，不会继续旧进程，也不会自动恢复智能体之前的任务。部分历史画面可能无法完整恢复。远端任务的重启边界见下文。

## 连接远端终端

Remote 集成在 SuperTerminal 中，无需再安装一个 DSH Remote 插件。

1. 在本机 SSH 配置中准备一个明确的主机别名，例如 `dev-box`。先通过系统 SSH 完成首次主机身份确认，并确保当前认证可以免交互登录；插件不会弹出密码或主机信任确认。
2. 在远端安装 `tmux`，并确保登录 Shell 能找到它和需要使用的 Agent CLI。
3. 使用已有 **Full access** 权限的来源对话打开终端。其他访问模式不能限制远端文件操作，因此不能启动远端任务；插件不会自动更改对话权限。
4. 选中一个空窗格，点击 **SSH**，选择主机，填写远端绝对目录。`~` 表示远端主目录。点击 **检查连接**，确认显示的主机、实际目录和检查时间。
5. 选择 Shell 或检查中发现的智能体。运行时窗格顶部一直显示执行主机与目录。

远端智能体使用远端已有的登录、模型与配置，不复制本机账号。连接检查只确认 SSH、tmux、目录与启动程序，不证明 CLI 登录、模型连接或套餐额度可用。相关信息需要在远端 CLI 中核对。

| 操作 | 对远端任务的影响 |
| --- | --- |
| 收起窗格、收起侧栏 | 保留原进程，可再次显示。 |
| SSH 连接中断 | 暂停输入，保留已有画面与页面草稿；点击 **重新连接** 接回原任务，不重发指令。 |
| 结束任务 | 停止这个终端对应的远端任务；失败时保留重试入口。 |
| 关闭或重启 DSH | 尝试清理所属任务；当前不保证跨 DSH 重启续接。异常退出或远端不可达时，远端进程可能仍运行，需在原主机核对。 |

重新打开页面时可以接回当前 DSH 服务仍管理的终端。若原记录已不在服务中，会显示 **重新选择远端**，不会悄悄启动本机任务或自动重跑旧任务。修改 SSH 别名指向后，原任务不会自动转移到新机器。

远端支持原生 Shell / Agent CLI、分屏、尺寸调整及显式选区的解释建议。**DSH AI 执行、自动 Agent 交接与 Terminal Group 暂限本机**，远端 Shell 也暂不生成命令块；需要 AI 在远端干活时，请使用远端 Agent CLI。助手建议会说明所帮助的远端目标，仍需你检查后执行。

远端输出经 SSH 传回本机显示，不会自动发送给模型。解释请求只共享你明确附上的选区；浏览器恢复记录包含远端别名与目录，不保存 SSH 密钥。alpha.13 已在 macOS arm64（tmux 3.7c）与 Linux x86_64（tmux 3.2a）远端实机验证连接、终端尺寸调整、断线重连与任务清理；alpha.16 沿用该执行实现。该次验收未覆盖远端模型执行、登录套餐或额度；当前仍不保证跨 DSH 重启续接。

## 助手知道正在帮助哪个任务

先点击一个终端，再打开 **助手**；窄侧栏使用 **更多 → 解释与建议**。助手顶部的 **正在帮助** 和结果中的 **建议用于** 会标明目标任务，方便你核对。

描述目标或粘贴报错后，点击 **生成建议**。也可以在终端中选中一段输出，预览后勾选 **附上这段输出**，再生成建议。未勾选的内容不会随请求发送。

建议中的命令可以复制，也可以点击 **填入草稿** 放到目标终端的“待发送草稿”中。草稿不会输入到终端或自动执行。请先检查内容和终端当前状态，再复制、粘贴；智能体的聊天输入框与 Shell 命令行用途不同。

选中终端文字后，可就地选择 **解释**、**建议修复** 或 **交给 Agent**。操作会预填目标与选区，点击生成或提交后才发送；不会直接执行命令。助手始终显示关联对话与正在帮助的终端。

问题草稿、上次建议、选区共享选择和待发送草稿按对话与终端分别保留。切换终端、收起助手或侧栏后再回来可以继续；这些内容只保存在当前页面的内存中，刷新页面后清除。最多保留最近 16 个工作台，每个工作台 24 份终端上下文。切换目标不会把上一项任务的建议填入另一个终端。

## 查看真实命令记录

在内置 Shell 下方展开 **命令记录**，查看每次命令的输出、用时与退出状态。可以折叠输出、复制命令，或把失败记录交给助手解释。命令记录来自 Shell 的实际执行边界；智能体 CLI 保持原有交互界面。

记录留在当前终端进程的本地内存中，最多 50 条、单条输出最多 32 KB；页面显示最近 20 条，截断时会提示。重新连接同一终端可继续读取，结束终端或重启 DSH 后不保留这些记录。Shell 配置不兼容时会说明原因，原生终端仍可使用。

Side Terminal 每次突出一个辅助面板，当前对话与目标终端始终可见。连接中断时保留已有画面和草稿，集中显示恢复状态；不自动重发未确认送达的输入。

## 把多个终端加入讨论组

**Terminal Group** 属于当前工作台。打开 **讨论组 → 新建讨论组**，为讨论命名并选择成员；窄侧栏从 **更多 → 终端讨论组** 进入。也可以拖动终端标题到组上，或使用该终端的 **更多 → 加入讨论组**。每组支持 1 至 6 个终端，同一个终端在组里只能选择一种参会身份。加入组不会移动、关闭终端，也不会直接向 Shell 或 CLI 输入自然语言。

### 先确认谁在参会

成员设置会列出当前可用的参会方式：

| 方式 | 上下文与身份 |
| --- | --- |
| **终端 DSH AI** | 使用该终端已有的 DSH AI 会话，沿用其模型、权限与自身历史。回复标明 DSH AI，并显示能够确认的模型。 |
| **独立 CLI 任务** | 当前支持 Pi / piagent 和 Codex。每次发言启动新的独立任务，使用当前工作区的 CLI 配置，不续接原生终端中已打开的 CLI 对话。 |
| **其他 CLI** | Kimi Code 等仍可在原生终端中交互，暂不支持自动 CLI 参会。选择它所在终端的 DSH AI 时，实际参会者是 DSH AI，不是那个 CLI。 |

已安装不代表已经登录或拥有可用额度；CLI 的登录与连接由实际任务确认。没有可靠的模型信息时，回复不会猜测模型名称。暂时没有可用成员时，请检查当前 DSH 会话的模型设置，或在智能体列表确认 Pi / Codex 已安装并启动对应终端，再点击 **重新检查**。

### 指定成员，讨论一轮或两轮

输入问题，点击输入框上方的 **发给 N 位** 选择成员，再点击发送。成员之间不会自动转发所有终端输出。已关闭或暂不可用的成员会标出原因；调整参会对象后再发送，原草稿保持不变。

- **1 轮 · 收集意见**：所选成员根据相同的组内材料，分别发表意见。
- **2 轮 · 相互讨论**：完成第一轮后，所选成员可以参考第一轮回复继续讨论。

例如，可以写：“请分别从实现与验证角度评审这个修改，指出风险和下一步。”回复会显示成员、参会方式、轮次和来源终端。没有完成的发言会说明状态；正常返回也不代表意见已经被其他成员认可。

如果需要共享报错或代码输出，先在终端中选中文字，在讨论输入区点击 **＋ 附选段**，再点击 **已附选段** 预览；发送前可取消。加入组本身不会广播旧日志。终端 DSH AI 仍保留自己的既有上下文，参与者只把本次回复交给组内讨论；不要把它理解为清空历史的新会话。

输入框下方会注明本次共享内容。每个组分别保留问题草稿、所选成员、轮数与附上的选段；切换组或收起面板后可继续。草稿保留在当前页面内存中，刷新页面后清除。讨论记录保存在 DSH 本地，可在重新打开同一工作台后查看；较长的历史材料可能会截短。

较长的 DSH AI 回复可从组内 **分段查看完整结果**。共享给下一位成员或执行者的材料仍有长度限制，会明确注明省略部分。CLI 的结果只保留最多 16,000 字符，截断后会提示，未保存的部分不能通过原文阅读补回。

### 形成结论，再安排执行

至少有一条成员回复后，选择 **结论整理者** 并点击 **形成结论**。这是一位明确署名的成员对共享讨论的整理，包括共识、仍有分歧的问题、下一步及验收标准；它不是投票结果，也不意味着全员达成一致。

点击 **将结论交给 Agent 执行**，会打开已有的 Agent 协作面板，预填讨论组、原目标和结论。核对执行者、任务与验收标准后提交，才会开始执行。返回结果后选择验收或提出返工问题；返工继续保留原目标、上次结果及任务关系。讨论结束不会自动执行待办，也不会替你验收成果。

发言始终保留当时的成员身份；成员后来离组，历史仍可追溯。来源终端仍存在时可直接打开；已关闭时会明确提示。讨论空闲时可通过 **管理成员** 调整名称、参会者或参会方式。**归档讨论组** 会从列表隐藏该组，保留原终端。

### 停止、断线与恢复

**停止讨论** 只停止本组安排的发言，保留已经完成的内容，不会向无关的终端任务发送停止指令。成员正在处理其他任务时，可能等待或暂时无法参会；讨论组不会替你向那个任务追加要求。

断线时集中显示恢复状态，保留记录与草稿。操作是否送达尚不确定时，点击 **核对这次操作** 确认同一次提交，避免重复执行。刷新页面不会自动发送草稿；重启 DSH 后，未完成的讨论标为中断，不会自动重跑。旧终端已经结束时，先启动新终端并在组内调整成员，再明确发送下一次问题。

Terminal Group 使用已有的 DSH 会话、本地存储与 Agent 交接能力，无需额外运行群聊服务器或消息中转服务。组内记录跟随所属工作台，切换绑定对话与独立工作台不会迁移讨论。

## 把下一步交给搭档

选择一个来源终端，打开 **协作**；窄侧栏使用 **更多 → 交给 Agent**。填写任务目标与完成判据，选择接收者；如需分享终端内容，先选择文字，再勾选并预览摘录。

当前后台任务支持 **Pi Agent、piagent 和 Codex**。它们使用当前工作区的独立配置，需先完成登录或模型设置。其他 CLI 仍可在原生终端中交互使用。Codex 后台任务会先检查该工作区的 Codex 登录；仅配置自定义模型服务、没有 Codex 登录记录的用法，当前请通过终端交互使用。

提交后会建立独立的后台任务，来源终端继续保留。协作记录展示来源、执行者、运行状态和返回结果；可展开或复制已保留的结果，超过 16,000 字符时会截断并提示。提交后会直接定位到新任务。**已返回 · 待验收** 表示 Agent 已正常返回，需要结合目标核对成果。

勾选 **完成后将结果送回关联对话**，结果会加入发起任务的 DSH 对话，等待该对话处理。切换页面不会改变目的地；独立工作台的任务回到它自己的会话。未勾选时，也可以在结果卡片点击 **送回对话**。回传状态不确定时，可点击 **核对回传**，同一任务不会重复发送消息。

结果返回后，可以填写验收说明并选择 **验收通过**，或通过 **要求返工** 明确指出需要修改的问题。返工会建立关联的后续任务，带上原目标、完成判据和上次结果；来源终端已经关闭也可继续。较长的原结果会裁剪并注明，Agent 需要重新核查。

每次返工保留父子关系，可继续对后续成果安排下一轮。已经验收的成果不会再从同一记录返工；Agent 执行成功也不会自动替你验收。验收与返工记录在 DSH 重启后保留。

同时最多运行 2 项后台任务。每个会话分别保留最多 **32 条执行与返工记录**、**256 条 CLI 讨论发言记录**；讨论不会占用执行或返工的名额。每位 CLI 成员每轮发言占一条记录，达到对应上限时会提示，不会删除旧请求记录后重新执行。可单独停止任务；重启后未完成的任务会保留中断记录，不会自动重跑。交接不会接管来源终端的键盘，也不代表继续接收 Agent 的旧会话。

## 账号与配置

打开 **更多 → 智能体管理**，按 **已安装／全部智能体** 筛选，使用名称或实际命令搜索，例如 `zsh`、`codex`。搜索会忽略首尾空格与大小写。卡片显示可识别的版本、使用配置和状态依据。

Codex、Claude、Kimi 和 Pi 在当前工作区使用独立配置。即使你已在其他终端登录，在这里首次使用仍可能需要重新登录。其他工具使用本机配置，并遵守 DSH 的访问权限。

检测未完成时显示进度；失败后可 **重试**。重新检测失败会保留上次结果和成功检测时间，恢复后才能启动。连接恢复中或终端位置已满时，“在本机打开”按钮也会暂停，并在当前页说明原因。重新检测、检查登录或点击说明文字后，仍可按 **Esc** 关闭管理页。

目录分别显示 **安装、登录、模型连接、套餐与额度**，并标明各自的检查时间。“已安装”只表示检测到了启动程序。

Codex 与 Claude Code 可点击 **检查登录** 进行本地核对，检查不会发起模型任务。Pi/Codex 的完整后台任务会留下当时的认证与模型连接证据，显示“上次连接成功”；这不保证此刻仍然在线。没有可靠证据时显示“未知”。套餐和余额未提供统一查询方式，具体数值请在对应智能体中查看；已知额度限制会根据最近任务注明。

部分安装方式无法读取版本号，会显示“版本未识别”。旧版任务若没有独立的执行结束时间，不会被用来推断刚刚完成了连接检查。

工作区中的 `.dsh-terminal` 保存本地运行数据，请勿提交或分享；使用中的数据目录也不应删除。

## 智能建议与隐私

在 **AI 任务** 点击发送，会把目标、该执行会话已有的历史和你明确附上的选区交给 DSH 模型。AI 可按任务需要调用当前智能体配置允许的工具读取文件、修改代码或执行命令，受页面显示的工作区权限约束。执行历史保存在 DSH 本机会话存储中；浏览器草稿只保留在当前页面内存，刷新后清除。

点击 **生成建议** 时，终端助手使用 DSH 已配置的模型，发送本次输入、所选终端的运行状态，以及你明确勾选的输出摘录。它不会自动读取其余终端内容、对话历史、工作区文件或智能体登录凭据。模型费用按所选服务的计费规则计算。

浏览器的本地存储只保存恢复工作台所需的名称、布局和关联信息，不保存终端输出、助手问题或草稿。

交接任务的目标、完成判据、显式分享的摘录和返回结果保存在 DSH 本地存储中。提交任务时会把这些选定材料交给接收 Agent；回传对话会发送任务与结果，不附带其余终端历史。

安装 **DSH Supervisor** 后，可在工作台查看它对当前对话的建议。任务回传后，来源、执行者、目标和结果会进入关联对话。

直接读取终端协作状态的 Supervisor 适配已在隔离环境验证，**尚未包含在公开 Supervisor 0.2.4 中**；本包不会替换或升级 Supervisor。适配接口提供任务目标、完成判据、来源与执行者、运行、回传、验收状态及返工关系，不提供原始终端输出。更新后的本地适配也能区分待验收、用户已验收与正在返工。正常返回和退出码 0 都不代表任务已经验收。

## 使用提示

- 连接中断时会暂停输入并尝试重连；尚未确认送达的输入不会自动重发。
- 当前为 Alpha 版本，尚不包含 Harvis 接管、任意 CLI 的后台协议适配或智能体任务的自动续接。
- 升级 DSH 前，请先确认 SuperTerminal 是否支持目标版本。
